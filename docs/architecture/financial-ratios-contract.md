# Wskaźniki fundamentalne — kontrakt etapu P2-04a

Nowy read-only endpoint GET /v1/panel/reports/{report_id}/{revision}/financial-ratios. Brak migracji, mutacji, pobrań i modelcalls. Nie zmieniamy financial_history.py ani modułów podpisanych kwalifikacją AI. Źródło: build_financial_history z archiwów wybranych przez istniejący endpoint historii.

Response FinancialRatios: report_id UUID, revision int>=1, report_checksum sha256, as_of timestamp, methodology_version literal sec-ratios-v1, history FinancialHistory (pełny, umożliwia niezależne sprawdzenie operandów), ratios lista maks12 punktów (4 wskaźniki x3 okresy), limitations lista tekstów. Punkt: metric literal net_margin/operating_cash_flow_margin/capex_to_revenue/free_cash_flow_margin; period_start/end CalendarDate; status available/unavailable; value_percent PercentString|null (6 miejsc HALF_EVEN); reason literal MISSING_INPUT/PERIOD_MISMATCH/FILING_MISMATCH/NON_POSITIVE_REVENUE/NEGATIVE_CAPEX|null; available_at timestamp|null; operands lista {metric literal revenue/net_income/operating_cash_flow/capital_expenditures, value DecimalString, source_snapshot_id UUID, source_sha256 SHA256} max3. Dla unavailable value null, reason wymagany; operands tylko istniejące zgodne z okresem. Periods to sorted union wszystkich okresów z historii, ostatnie3. Każdy okres4punkty nawet przy brakach. Pusta historia -> pustalista.

Wzory: net_margin=net_income/revenue*100; operating_cash_flow_margin=operating_cash_flow/revenue*100; capex_to_revenue=capital_expenditures/revenue*100; free_cash_flow_margin=(operating_cash_flow-capital_expenditures)/revenue*100. Ostatni to ograniczony proxy FCF, nie pełny przepływ dla właścicieli ani wycena. Revenue>0, capex>=0; negative netincome/OCF dozwolone. Exact Decimal context>=512, output max128digits, HALF_EVEN6places; zero canonical0.000000. Wymagane exact start/end,currencyUSD i ten sam niepusty filing_accession wszystkich składników. Brak serie ->MISSING_INPUT; seria z innym okresem ->PERIOD_MISMATCH; accessionnull lub różne ->FILING_MISMATCH. Zachowaj wcześniejsze priorytety: missing,period,filing,denominator,capex. available_at max składników tylko dla available. Nie wyciągamy ratingu ani przyczyn, rekomendacji, standardowych progów dobre/złe.

Właściciel Backend: nowe financial_ratios.py, financial_ratios_api.py, test_financial_ratios.py,test_financial_ratios_api.py. Koordynator API include/schemaexports i integracja. Frontend: nowe financial-ratios-state.ts,financial-ratios.tsx,tests/financial-ratios-state.test.mjs; bez main.tsx. Frontend waliduje history przez istniejący assertFinancialHistory i niezależnie exact BigInt wyliczenia/status/provenance/identity. Render tabela wskaźników, okres/%, braki z kodem i jasnym opisem; operandydowody w details. Bez sugestii inwestycyjnych. QA osobno read-only poimplementacji.
